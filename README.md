# VPN Config Tester

Консольное приложение на C# (.NET 9.0) для тестирования доступности VPN серверов из конфигурационных файлов и анализа IP-диапазонов успешных серверов.

## 🚀 Возможности

- **Автоматическое скачивание конфигурации** по ссылке или **использование локального файла**
- **Парсинг VPN конфигураций** с поддержкой множества протоколов:
  - VLESS
  - Trojan
  - VMess
  - Shadowsocks (SS)
  - Hysteria / Hysteria2
- **Параллельное TCP тестирование** серверов с настраиваемым лимитом одновременных подключений
- **Сохранение результатов** в структурированные файлы
- **Анализ IP-диапазонов** успешных серверов с группировкой по подсетям
- **Генерация рекомендаций** по фильтрации IP-адресов
- **Безопасная обработка данных** с защитой от ReDoS атак

## 📋 Требования

- .NET 9.0 SDK или выше
- Доступ к интернету для скачивания конфигурации
- Операционная система: Windows, Linux, macOS

## 🛠️ Установка

1. Клонируйте репозиторий или скачайте проект

   ```bash

   ```
3. Соберите проект:

## 📖 Использование

### Основной режим работы

Запустите приложение без аргументов для полного цикла тестирования:

```bash
dotnet run
```

Приложение выполнит следующие шаги:
1. Скачает конфигурацию VPN из GitHub (или использует существующий файл)
2. Дождется подтверждения пользователя (нажатие любой клавиши)
3. Распарсит конфигурацию и извлечет серверы (поддерживает VLESS, Trojan, VMess, Shadowsocks, Hysteria)
4. Протестирует доступность серверов через TCP подключение
5. Сохранит результаты в файлы
6. Выполнит анализ IP-диапазонов

### Режим локального файла

Для использования уже существующего конфигурационного файла без скачивания:

```bash
dotnet run -- --skip-download
# или короткая форма:
dotnet run -- --local
dotnet run -- -l
```

Этот режим:
- Пропускает загрузку конфигурации из интернета
- Использует файл `source_config.txt` из текущей директории
- Полезен для тестирования собственных конфигураций
- Экономит время при повторных запусках

### Режим анализа существующих данных

Для анализа уже протестированных серверов используйте флаг `--analyze` или `-a`:

```bash
dotnet run -- --analyze
```

Этот режим:
- Прочитает файл `successful_servers.txt`
- Проанализирует IP-диапазоны
- Выведет статистику и рекомендации
- Сохранит диапазоны в `ip_ranges.txt`

## 📄 Выходные файлы

После выполнения приложение создает следующие файлы:

- **`source_config.txt`** - Исходная конфигурация, скачанная из GitHub
- **`successful_servers.txt`** - Список успешных серверов в формате `IP:PORT`
- **`output_config.txt`** - Отфильтрованная конфигурация только с успешными серверами
- **`ip_ranges.txt`** - Рекомендуемые IP-диапазоны для фильтрации в формате CIDR

## ⚙️ Конфигурация

Настройки приложения находятся в классе `ApplicationConfiguration`:

```csharp
public class ApplicationConfiguration
{
    public string ConfigUrl { get; init; } = "...";           // URL конфигурации
    public int TcpTimeoutMs { get; init; } = 3000;           // TCP таймаут
    public int MaxConcurrentTests { get; init; } = 50;       // Макс. параллельных тестов
    public int HttpTimeoutSeconds { get; init; } = 30;        // HTTP таймаут
    public int MinIpCountForSubnet24 { get; init; } = 3;     // Мин. IP для /24
    public int MinIpCountForSubnet16 { get; init; } = 5;     // Мин. IP для /16
}
```

### Основные компоненты

1. **ConfigDownloader** - скачивание конфигурации из интернета
2. **ServerParser** - парсинг URL конфигураций:
   - VLESS (vless://)
   - Trojan (trojan://)
   - VMess (vmess://) - с base64 декодированием
   - Shadowsocks (ss://) - с base64 декодированием
   - Hysteria (hysteria://, hysteria2://)
3. **ServerTester** - параллельное тестирование доступности серверов
4. **ConfigWriter** - сохранение результатов в файлы
5. **IpRangeAnalyzerService** - анализ и группировка IP-диапазонов

## 🐛 Устранение неполадок

### Проблема: Не удается скачать конфигурацию

**Решение**: Приложение автоматически использует существующий файл `source_config.txt`, если он есть в директории. Или используйте флаг `--skip-download` для явного указания использования локального файла.

### Проблема: Протокол не поддерживается

**Решение**: Убедитесь, что используете один из поддерживаемых протоколов: VLESS, Trojan, VMess, Shadowsocks, Hysteria, Hysteria2. Если протокол не распознается, проверьте формат URL.

### Проблема: Медленное тестирование

**Решение**: Увеличьте `MaxConcurrentTests` в конфигурации (осторожно с нагрузкой на сеть).

### Проблема: Таймауты при подключении

**Решение**: Увеличьте `TcpTimeoutMs` в конфигурации для медленных сетей.
